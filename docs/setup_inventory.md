### Exact option lists and dynamic text
- Dialogue: `Detect automatically` → auto; `English` → en; `Another language (clean the subtitles only)` → foreign (gui/pages.py:170-172). Tooltip explains foreign dialogue is not silenced and subtitles are cleaned/set to show (173-175). Audio option text is `{language} · {layout or N ch} · {CODEC}` plus optional `"{title}"`; unknown language is `Unknown language` (media.py:214-219).
- Subtitle style: `****` → stars; `f***  (first letter)` → first; `a cleaner word (freaking, crap…)` → word (gui/pages.py:204-206). Burned subtitles: `Check foreign-language films` → auto; `Always check (slow)` → on; `Don't check` → off (214-216).
- Blur size: `Tight` → tight; `Normal` → normal; `Large (moving actors)` → large (gui/pages.py:292-293).
- Every scene group's How picky: 1 `Only obvious`, 2 `Fewer flags`, 3 `Balanced`, 4 `More flags`, 5 `Flag anything suspicious`. Beside slider is a QLabel showing that exact current string, disabled with slider. Every group's What to do: `Cut it out` → cut; `Black screen + silence` → black; `Black screen (keep sound)` → black_keep; `Blur just the private parts (keep sound)` → blur_parts; `Blur the whole picture (keep sound)` → blur; `Silence the sound only` → mute (gui/scenepicker.py:11-16,80-100). The selected-label QLabel is included with each slider table row.
- Advanced mode: `Silence (default)` → mute; `Replace with a spoken clean word` → replace; `Replace + match the lips (experimental)` → replace_lipsync. Voice: `Windows voice (built in, works offline)` → windows; `ElevenLabs (online, uses your own credits)` → elevenlabs (replace.py:26-31).
- Advanced note concatenates, separated by a space: `Lip-sync is experimental: it needs a MuseTalk install of your own and an NVIDIA card (Settings → Advanced Editing), and the video is re-encoded.` when mode replace_lipsync; `ElevenLabs sends only the replacement word (not the movie) over the internet and uses your credits. You'll be asked to confirm before anything is spent.` when engine elevenlabs (gui/pages.py:465-472).
- Footer note: `Already listened to — a new scan only takes moments (unless scenes are new).` for cached track; otherwise `First scan downloads the speech model (about {gb:.1f} GB, one time only).` for missing speech model; otherwise empty (gui/main.py:258-266). Loading uses each group-specific sensitivity/action dictionary entry, falling back to global sensitivity/action (gui/pages.py:403-406), so Kids displays 4 in all groups and Everything 5, including disabled groups.

- Settings.all_presets() starts with built-ins then overlays user presets by name; a saved same-name preset overrides a built-in. Combo follows dictionary order then adds Custom. set_movie applies **settings.filters**, then sets combo to last_preset if its name exists, without verifying equality or reapplying that named preset (settings.py:88-91; gui/pages.py:371-379). Thus displayed name and values can disagree after a Save as preset without scanning.
- Activating a real preset applies FilterOptions.from_dict(snapshot), sets combo name, and does not persist immediately; activating Custom applies nothing (gui/pages.py:481-485). Header audio/dialogue are not included in presets.
- Filter control edits call _changed(); it compares the complete asdict(filters()) against normalized preset dictionaries, chooses the **first exact match**, otherwise Custom. It does NOT always simply mark Custom, nor does it use fuzzy/effective-behavior matching. Audio and Dialogue have no _changed connection; expanding Words is UI-only and does not change preset (gui/pages.py:165,169-175,453-459; gui/wordpicker.py:107-110).
- Important static mismatch: filters() always emits global sensitivity=3, scene_action="cut", plus explicit scene_sensitivity and scene_actions entries for **all four groups**. Built-in snapshots have empty per-group dictionaries (and Kids/Everything global 4/5). Therefore an edit and restoration cannot exactly match raw built-ins under this comparison: ordinary filter edits after choosing a built-in normally display Custom, even when visually restored. Saved user presets created by filters() have the expanded structure and can match. Selecting a built-in explicitly still displays its name because _preset_chosen sets it after apply (gui/pages.py:410-429,453-458,481-485; settings.py:23-26,46-57). This is a source deduction, not a runtime reproduction.
- Save as preset: modal QInputDialog title `Save preset`, prompt `Name for these settings:`; canceled or whitespace-only name does nothing. Trimmed name stores asdict(filters()) in SetupPage._presets; inserts new combo item before Custom (existing names overwritten without confirmation), selects name, emits savePreset(name,dict). Main stores settings.presets[name], settings.last_preset=name and immediately saves JSON. It does **not** update settings.filters here (gui/pages.py:487-496; gui/main.py:280-283). Name `Custom` is not reserved by validation and may create an entry with that name.

## Header, footer and scan gating

Header back button occupies its own row, then filename heading, then file summary / Audio / Dialogue row (gui/pages.py:152-178). Audio selection changes Project.audio_track and recalculates footer note, without calling Project.save directly. Dialogue combo is read at scan time. Neither affects the preset name. Main will not open no-audio files (gui/main.py:246-252,268-271,335-339). Setup's body is one scroll area with Language, Scenes, Advanced Editing stacked; header/footer remain outside it (gui/pages.py:180-188,267,302-358).

Footer order is Preset, Save as preset, stretch, note, Use an edit list instead…, Scan movie (gui/pages.py:340-358). Scan button disabled ONLY when all four selection sources are empty: no checked predefined words, no trimmed custom words, no checked scene types, no trimmed custom descriptions (473-479). Allow-list, fades, subtitle cleaning, blur defaults and advanced settings alone do not enable it; a nonempty allow-list does not disable it even if it suppresses all matches. The main scan handler also returns for busy/no project, may stop for declined disk-space relocation, and may prompt for GPU pack; these are handler checks, not button-disabled conditions (gui/main.py:331-358). Setup edit-list click invokes _load_edit_list, with file validation/movie-match prompts before adopting filters/review (gui/main.py:93,589-623).

## Persistence between sessions

- Settings.save serializes **every Settings dataclass field**, including nested filters/presets, to app_data_dir()/settings.json, indented JSON via write_atomic; load accepts known keys and falls back to fresh defaults on any exception. FilterOptions.from_dict separately ignores unknown fields and migrates legacy nudity/sexual scene keys (settings.py:30-42,93-104; paths.py:18-30).
- Directory resolution: PRUDE_DATA_DIR override, otherwise (LOCALAPPDATA or XDG_DATA_HOME or ~/.local/share)/PrudeAwakening. On ordinary Linux this is ~/.local/share/PrudeAwakening/settings.json; Windows commonly %LOCALAPPDATA%/PrudeAwakening/settings.json. This investigation did not read live user settings or secrets (paths.py:41-46; __init__.py:4-5).
- Persisted Settings fields and declared defaults (settings.py:61-81): output_dir="", models_dir="", device="auto", speech_model="", video_quality="high", keep_subtitles=true, make_subtitles=true, blur_thumbnails=true, gpu_pack_declined=false, check_updates=true, last_update_check=0.0, elevenlabs_key="", musetalk_dir="", musetalk_python="", last_preset="Family night", filters=Family-night snapshot, presets={}, recent=[], export={}, window=[]. Advanced API key is a persisted field; no value was accessed in this audit.
- Setup filters and current preset name persist at **start_scan**, before downloads/space checks or worker success (gui/main.py:334-342); choosing/editing controls alone does not save them. Save as preset immediately persists the named snapshot and last_preset, but not the current filters. Normal close saves window geometry and the existing Settings object, not unsaved SetupPage controls (gui/main.py:280-283,703-705). Opening a movie saves recent files, not in-progress control values (251-255).
- Audio and dialogue are Project fields, stored in projects/<project-key>/project.json when Project.save runs, not global Settings/preset fields (project.py:115,124,143-177; paths.py:49-52). Audio's UI handler only mutates memory; Dialogue mutates at scan start; subsequent project saves persist them. No claim that changing either combo immediately writes project.json. Word-panel expansion, tri-state summary text and scroll position have no Settings fields.

## Words: not a popup, and what “all” means

Words is an inline expandable QFrame in each WordCategory, not a dialog/popover. Initial panels are hidden; button changes ▸ to ▾; child checkboxes stay enabled when their parent category has zero selected words (gui/wordpicker.py:49-80,107-110). Each word checkbox represents a **labelled group of spellings/patterns**, not just one literal token. Definitions come from data/words/<category>.txt; `label: pattern, pattern` or a bare pattern is parsed, blank/comment lines ignored (words.py:33-51). Tooltips list caught forms, replacing wildcard stars by ellipses; slurs show only `{n} spelling(s)` after `Catches: `, though checkbox labels still come directly from the file (gui/wordpicker.py:10-16,69-75).

Category header `all` is a count QLabel, not a clickable extra option: shown when all word-group checkboxes in that category are checked; partial count is `{on} of {n}`; none is blank. Header category checkbox is checked/partial/unchecked accordingly; clicking partial selects all, clicking checked clears all (gui/wordpicker.py:19-23,113-128). Panel `All`/`None` buttons affect only that category; top-level Language `Select all`/`Select none` affects all five categories. Disabling a whole category produces no excluded_words entries; partially selecting records unchecked group keys only, while category remains in F.words (gui/wordpicker.py:84-105). Thus “all” means all bundled groups **in that category**, not all language categories, not all possible profanity, and not a count of every spelling. Allow-list suppression still applies in pattern matching (words.py:58-83).
